# 1. 数据集、划分和风险

## 1.1 当前可识别的输入结构

用户提供的本地材料中有农业文本对和三个公共基准的候选处理版本，具体文件角色列在 [`datasets.json`](../configs/datasets.json)。它们的来源、使用权、数据处理历史以及是否为论文最终版本，均需进一步核实。文件名中的 `_S` 不应被解释为官方划分。

当前候选文件采用 JSON Lines：每个非空行一个 JSON 对象，字段 `sentence1`、`sentence2`、`gold_label`；标签可能为字符串或整数，`0` 为不匹配、`1` 为匹配、`-1` 表示该记录未提供监督标签。加载时统一为整数并校验，不允许把 `-1` 送入二分类 CE。

| 配置ID | 本地目录 | 训练候选 | 标注子集参考 | 验证 / 测试候选 |
|---|---|---|---|---|
| agriculture_local | Agriculture9_S | train_50.txt | train_sup_50.txt | dev.txt / test.txt |
| lcqmc_local | LCQMC_S | train.txt | train_sup.txt | dev.txt / test.txt |
| pawsx_local | PAWSX_S | train.txt | train_sup.txt | dev.txt / test.txt |
| afqmc_local | AFQMC_S | train.txt | train_sup.txt | dev.txt / test.txt |

农业训练候选为标注与 `-1` 混合文件；不能仅凭数量或文件名认定 `-1` 记录来自农业微调的某个生成模型。公共基准的训练候选中存在原始 0/1 标签；将其用于无标签池时，必须先从训练池中排除所选标注样本及其等价重复项，再**在模型、采样器和日志接触前**剥离标签，只保留内部匿名ID和文本。不得把开发／测试标签混入训练。

可替代测试文件只是保留的候选，不能自动用来替换原测试。`train_sup` 和 `train` 的对应关系需要先审计；若文件版本不一致，应停止并追溯，不能随机取交集后假称原始实验。

## 1.2 版本登记与权限

1. 为每个来源记录：数据名称、发布者／取得方式、版本、下载或取得日期、使用许可、中文子集、原始划分和本地转换版本；不明处写“未知”。
2. 在本地对每个输入文件计算 SHA-256，记录代码版本、处理脚本版本及数据快照。不要把原始文本、私有路径或逐条结果上传到公开仓库。
3. 如果来源、许可或项目内训练使用权未确认，先停留在只读检查；如果允许训练但不允许分享，只在本地训练。候选模型也需逐一审查许可证。
4. 论文提到的数据规模、生成方式和抽样结果，是待对照的文献叙述；不是当前数据可直接继承的事实。不能用人工猜测补足来源或生成记录。

## 1.3 两条不同用途的数据协议

**A. 本地历史对照。** 原始文件只读保留，先运行精确审计。该轨道用于定位文件与学习旧流程；若有跨划分完整对、标签冲突、标注子集对应不上等风险，不能当作独立测试结果。原有实验设置不明时，不能称为严格复现。

**B. 新建的严格划分。** 在有权使用的数据上生成单独的数据版本。对已标注样本的两句建立图：规范化句子是节点，文本对是边；同一连通分量不得跨训练、验证和测试。固定种子 20261030，目标比例 80% / 10% / 10%，尽量保持类别比例；记录各分量大小、实际比例和类别数。冲突样本须隔离，标签须人工核对；不要根据测试性能选择划分、清洗阈值或样本。旧测试被重新分配到训练时，必须把它视为**新实验**，不能再称原测试独立保留。可执行步骤和近重复规则见[操作说明](08_clean_split_workflow.md)。

如果一个巨大连通分量使上述比例或类别覆盖不可行，不要强拆后声称句子独立；应公开报告约束不可行，选择有来源分组的独立数据或另行明确局限。源ID缺失时，句子不重合也不能声称来源不重合。

`scripts/component_diagnostic.py` 可在本地只读检查几个候选标注文件合并后的连通分量大小，不建立划分或更改输入。它按规范化及倒序去重；如果该任务不是对称匹配，必须先评估该假设。例子：

```powershell
python -B scripts/component_diagnostic.py --files `
  (Join-Path $agri 'train_sup_50.txt') (Join-Path $agri 'dev.txt') (Join-Path $agri 'test.txt') `
  --output 'reports\agriculture_components.json'
```

最大分量未超过目标比例是必要条件而非可行性证明；仍要检验完整分组的类别覆盖、分组大小、实际分配方案和来源信息。出现冲突或畸形记录时工具返回2并要求人工处理；报告不会输出文本。

对于 LCQMC、PAWS-X、AFQMC：先核对官方来源、版本、语言和许可。保留官方测试的实验与“新建句子独立划分”是**两条报告**；后者不能冒称官方基准结果。官方划分可能复用句子，需报告这种边界；如剔除训练样本或改变测试文件，必须将结果标记为修改后的协议，不能与官方结果直接当作同一设置。

## 1.4 泄漏与质量审计

仓库内脚本检查 NFKC 归一化、去 Unicode 空白后的精确文本对、逆序对和跨文件单句。逆序检查默认保守：对于非对称任务，结果是待人工核实的候选。脚本还检查冲突标签、评估集的无标签记录和监督子集与训练文件的对应关系。归一化可能合并原本不同的字符串，冲突是**待复核信号**，不是自动纠正的依据。

精确审计之外还需要：

- 用固定方法检索近重复候选，公开记录阈值、召回抽检与人工裁定；不得宣称已经排尽所有语义等效样本。
- 对有 source_id 的数据检查来源重叠；没有来源信息就如实标记“无法验证”。
- 对外部无标签数据，排除与验证／测试相同的对及严格协议下共用句子的记录，并核对生成器／微调语料是否可能见过测试文本；无法追溯时如实记录。
- 字符词表、归一化规则的统计量和任何可学习预处理只在划分完成后的训练数据上拟合；验证与测试不得参与词表构建。
- 每个步骤保留输入哈希、代码版本、种子、剔除数量和原因；不要覆盖原文件。审计报告、样本ID与原文仅保存在本地。

本地资料提示至少部分候选存在跨划分重合或版本不一致，必须以实际脚本输出和人工复核为准。这说明候选文件需要治理，并不证明任何第三方论文的最终实验使用了同一版本。

## 1.5 标注比例与无标签池

建议 LDP 为 10%、15%、20%、25%、30%、35%、40%、45%、50%，分母是**审计并锁定后的标注训练池**，不是整个训练加无标签文件。每个训练种子下对各类使用固定随机排列取前缀，从而九档嵌套；记录原始、目标和实际每类数量、取整规则、每档ID与种子。若某档不能覆盖全部类别，停止并调整预先定义的规则。

比较模型共享同一数据版本、划分、LDP和对应标注ID；所有会使用U的方法在同一比较中共享同一U池。U数量上限15,000，实际量为 `min(15000, 可用的训练U数量)`，先按固定种子选取并记录；规模消融分别用25%、50%、100%。农业外部候选U与公共基准“剩余训练数据去标签”的U来源不同，需分开标识，不能混为一种条件。监督模型不使用U，报告时明确这是一类不同训练信息量的比较。

## 1.6 生成无标签数据的来源与质量抽检

若要使用外部生成的U，先登记实际可追溯的信息：生成模型的确切名称与版本、许可、领域微调数据来源及其与评估数据的可能关系、微调配置、提示模板、解码和采样参数、生成日期、候选数量、过滤／去重规则及每一步保留数量。当前本地候选记录的生成来源尚未核实，**不能仅凭文件名认定生成器、提示或训练语料**；无法追溯时明确写未知，也不能声称已排除生成器预训练或微调阶段的污染。

建议对过滤前的候选输出和最终拟用U分别保留本地审计清单；筛选标准在抽检前确定，记录被过滤数量与原因，原文及逐条标注仅保存在有权限的本地环境。对最终U，可按固定种子 `20261030` 从锁定的记录集中不放回简单随机抽取 `min(500, 可用记录数)` 对作质量抽检，保留匿名记录ID、抽样程序和分母。若抽检前后数据发生变化，应重新登记版本；重复样本及相关来源组会影响统计独立性，需在报告中说明并考虑按来源组评估不确定性。

抽检前写明判定手册，并建议由两名熟悉领域的人员独立、盲法判断每对是否满足预先定义的中文可理解性、任务相关性和两句关系可判断性；分别记录各项判定、分歧和仲裁结果。公开报告最终各类别数量、有效率、计算分母、抽样方式及一致性指标；若样本和判定满足独立二项抽样假设，可给95% Wilson区间，否则说明或采用适合分组的区间方法。抽检量500是**本项目建议**，不是原论文抽检结论；抽检不能代替完整泄漏审计或来源授权核验。

无标签对可以是匹配也可以是不匹配；“语义可理解／关系可判断”不等于它们必然匹配，更不等于伪标签正确率。若要测伪标签准确率，需要独立获得可靠的人工匹配标签并说明抽样和评价口径。原论文中已有的质量数字及评价记录仍待溯源，不能用本项目未来的抽检结果冒充原作者结果。
